# Event ID 257 - Phishing Alert: Deceptive Mail Detected


## Short Overview of the Investigation

This investigation examines a medium-severity phishing alert generated by LetsDefend's SOC282 detection rule. A suspicious email containing a malicious attachment was sent to an employee named Felix. My analysis revealed that the attachment delivered a Remote Access Trojan (RAT), followed by suspicious activity on the affected endpoint.

*Investigation verdict*: True Positive - Phishing with confirmed malicious execution.

## Investigation Steps 🕵️‍♂️

1. ### Email Analysis
I reviewed the sender, recipient, email content, SMTP address, and attachment. The sender domain and source IP were suspicious, and threat intelligence checks identified the source IP as malicious.

2. ### Malware Analysis
I downloaded and analyzed the attached ZIP file in a sandbox. The extracted coffee.exe was identified as Backdoor.Marte.VenomRAT, a remote-access trojan capable of enabling unauthorized access to a compromised system.

3. ### Endpoint and Network Investigation
I investigated activity associated with Felix's endpoint. Browser history showed access to the infected file, while network logs identified suspicious connections, including 37.120.233.226.

The process tree showed: explorer.exe → coffee.exe → cmd.exe

Terminal history included commands such as systeminfo, hostname, net user, tasklist /svc, ipconfig /all, and route print. These commands are consistent with system, account, process, and network discovery.

4. ### Containment
The documented walkthrough reports that the malicious email was deleted and the infected host was isolated from the network.


## My Findings, Conclusions and my Response 🔬

### Findings

- The suspicious email originated from free@coffeeshooop.com.
- The email contained a ZIP attachment that delivered coffee.exe.
- Malware analysis identified the executable as VenomRAT.
- Endpoint activity indicated execution and subsequent system reconnaissance.
- Network logs showed connections to suspicious infrastructure.
- The documented response included email deletion and host isolation.

### Conclusion 

The alert was classified as a *True Positive*. The evidence indicated that the phishing email led to malicious execution and compromise of the affected endpoint.

### My Response

1. I deleted the phishing email and searched for copies delivered to other users.
2. I kept the affected endpoint isolated while investigating.
3. I preserved the malicious attachment, file hashes, process history, and network indicators.
4. I investigated persistence, lateral movement, credential exposure, and possible data exfiltration.
5. I reset potentially compromised credentials and remediated the endpoint as appropriate.
6. I monitored the environment for related indicators of compromise.

## Lessons Learned ✍️

- Suspicious email attachments should be analyzed before being considered safe.
- Threat intelligence can help identify malicious sender infrastructure.
- Process trees and command history reveal what happens after a user executes a malicious file.
- Correlating email, endpoint, and network evidence helps establish the extent of compromise.
- Prompt containment and evidence preservation are essential during phishing incident
